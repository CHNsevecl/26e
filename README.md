# 26e 视觉拼图

C++17 / OpenCV 项目。`main.cpp` 获取图像，`a4_perspective_transform` 完成透视校正，`line_process` 识别拼块，`task` / `task2` 求解并保存结果。`main.cpp` 默认使用原有 GStreamer/libcamera 摄像头，也支持 `--image` 离线输入。识别流程不打开串口。

## 构建与验证

```bash
cmake -S . -B build
cmake --build build -j2
ctest --test-dir build --output-on-failure
cd build
./ps
```

图片和报告写入程序运行时的当前目录。运行 `ps` 会重新保存过程图片。

Debug 构建默认开启 `PUZZLE_OPTIMIZE_DEBUG`，为 GCC/Clang 加上 `-O2` 并保留调试符号，避免在 8 秒求解预算内因未优化代码而持续超时。需要逐行调试未优化代码时，可配置 `-DPUZZLE_OPTIMIZE_DEBUG=OFF`。

`task1` 调用原白色拼块流程，`task2` 调用扑克牌流程。task1 的求解预算为 8 秒，task2 的求解预算为 30 秒（节点上限均为 30000）；Python 分别最多等待 45 / 90 秒，包含摄像头预热、拍照与处理。每次识别失败后重新运行 C++，重新打开摄像头、预热并拍照；点击“停止”终止当前进程并取消后续重试。后台线程执行 C++，Tk 主线程只处理界面事件与图片显示。

## 黑色 A4 检测

`a4_perspective_transform` 的实现位于 `src/a4_detection.cpp`，原调用接口保持不变。检测结合随亮度变化的 Canny 阈值、多组黑色分割阈值和小范围闭运算，不再只选择最大外轮廓。四边形候选需要满足面积、凸性、形状、内部黑色占比及边框内外明暗差；额外检查紧贴边线的梯度，减少反光造成的边界内缩。纸张短边映射为 210 mm，长边为 297 mm，输出仍裁去四周 5 像素。

运行时保存 `a4_detection.png`（绿色边框和四角编号）、`a4_dark_mask.png`（黑色分割图）和 `edged_origin.png`（边缘图）。未检测到可靠边界时返回空图，主程序结束本次处理。测试覆盖杂乱背景、白色矩形干扰、弱光、模糊、噪点、照明渐变、局部断边和横放纸张。

## 拼图流程

新增的 `task2(const cv::Mat& warped)` 位于 `src/perspective.cpp`，用于将剪开的扑克牌碎片恢复为完整牌面，并计算机械摆放位置。`main.cpp` 先使用相同的黑色 A4 检测和透视校正，再通过 `--task2` 选择新任务；不带该参数仍执行原来的白色拼块 `task`。

```bash
# 在 build 目录运行；摄像头采集、识别和复原，不打开串口。
./ps --task2 --dry-run
# 识别并保存结果，同样不打开串口。
./ps --task2
# 仅显式调用发送入口才打开串口，发送该次保存的目标。
./ps --send-result /本次结果目录/machine_targets.json
# 使用现场原图离线验证，包含黑色 A4 检测。
./ps --task2 --dry-run --image /绝对路径/现场图片.jpg
```

`task2` 按背景亮度和颜色提取牌片、填充内部印刷孔洞，保留每块的真实彩色图像和掩膜；黑色印刷碰到切边时，仅在其颜色明显比外侧黑纸更暗、且缺口范围较小时修补，不直接将凹形碎片替换为凸包。牌片需分离摆放，间距应大于闭运算尺度；重叠、接触以及油墨与背景完全同色的切边仍可能无法正确分离。

背景使用黑纸像素拟合随位置变化的颜色和亮度，避免将受光较亮的黑纸误并入牌片。`task2_background.png` 保存背景估计。`task2_recognition.png` 中绿色为实体边界，青色为供拼接使用的直边模型；短圆弧不再被当作额外切边，真正的短直边和凹口仍保留。圆角过渡按边长判断弯曲程度；由少量噪声或端部圆角拆开的近共线边，仅在原始轮廓像素支持同一直线时合并，保留真正的短直斜边和凹切口。去除花纹形成的短圆弧后，还会合并由两组轮廓像素共同支持、且仅被向内弯曲花纹分开的近共线拟合直边，避免同一切边分成两段后因求交失败退回多边形噪声；偏移的平行边不合并。若原有拟合和小毛刺处理之后仍有多余凹折，再用轮廓像素的实际直线支持复查短边：长度至少 8 mm、仅端点让种子弦线弯曲的直切边可保留，不稳定的小花纹弧段则跳过。仅对这种退化轮廓的恢复，面积比较加入半像素边界量化误差带；最终覆盖率、重叠及框外面积验收阈值不变。稳定的已有模型保持原样，真正短直斜边、凹切口及圆角仍由回归测试保护。对超过四边且含凹折的模型，再以 3、5、7 像素椭圆开运算试探附着毛刺；仅接受仍为单连通块、轮廓面积至少保留 98% 且模型顶点减少的结果，稳定四边形和凸模型直接保留。此处理只用于估计几何模型。原始掩膜、圆角及牌面像素不由直边模型替代，原始重心取实体轮廓面积重心；最终机械重心由这个原始重心按求解得到的旋转、平移变换，避免使用圆角外推交点改变吸取位置。

近似直角的四边形也先检查原始轮廓的直边支持，不再只因种子顶点接近 90° 就跳过拟合，避免拍摄微差让圆角端点被误当成切边交点、缩小碎片模型。真实直边轮廓仍可保留原多边形；拟合的方向、面积和交点距离检查继续生效。若角标原始连通域找不到完整的字形与小花色组合，再用开运算分离字形与邻近牌框之间的细连接；仅用分离后的区域定位，匹配仍采样原始对比度图，保留细笔画。两个角标的字形、小花色及比例验收门槛保持不变。回归样本包含 `task2_ixseg_wr` 两次梅花 Q 的完整相机照片。

没有参考图时，先按轮廓生成几何候选，再根据接缝两侧的颜色、印刷连续性评分。对于普通白边扑克牌，还沿每条边向内 3、7、12 像素采样，并按每块自身的纸白亮度归一化，将白框位于最终外侧作为候选排序和最终评分的一部分，减少相似轮廓把白框拼到中间的错误。该规则是软评分，不放宽覆盖、重叠、框外面积等几何验收阈值；无白边的牌面可设置 `CardPuzzleOptions::use_white_border = false`。还比较直边模型顶点附近缺失的实体纸张比例，在近直角凸顶点中提取原牌圆角证据，使有圆角的顶点更倾向最终矩形四角，减少黑桃 A 等大面积空白牌片被交换后仍通过几何验收的错误。该证据同样是软评分，可通过 `CardPuzzleOptions::use_rounded_corners = false` 关闭；报告记录 `rounded_corner_prior`。报告分别记录 `seam_score`、`boundary_score` 和 `white_border_prior`。对不超过 8 块的结果，找到有效布局后为外观优化预留搜索预算，先尝试包围盒尺寸接近的两块交换位置并独立旋转 180°，再检查近矩形拼块组合的整体 180° 旋转，并按原有全部几何阈值重新验收和比较花纹评分。对最多 4 块，即使角标已经通过，也比较每块独立半转的组合（最多 16 组），防止无角标牌片单独转反；若角标未通过，还比较组合位置交换及独立半转（4 块最多 384 组），允许跨过单次交换不能改善的中间摆法；按角标及花纹排序后仍须通过完整几何检查，且不超出原有搜索预算。若独立半转需要稍大的整牌矩形，附加精调会在调整目标宽高的同时平移各块重心，跨过单独调边界或单独移牌片无法改善的中间状态；每个牌片仍只做刚性旋转和平移，减少相似形状导致整列方向颠倒。在搜索预算内比较多个通过几何验收的候选，保留评分较高的一组。纯白接缝、重复图案或整体 180° 对称可能产生多解；报告明确记录 `unique_solution_verified: 0`，不声称恢复了唯一正确的牌面。未找到几何有效结果时不保存可发送的机械目标。

完整布局还会在小尺寸牌面画布上检查左上和右下角标：定位“数字/字母在上、小花色在下”的组合，将右下角旋转 180° 后比较两组符号形状。角标使用 240×360 牌面画布，保留纸白归一化后的连续灰度，从角标列估计局部纸白和墨色对比度，再提取完整笔画并归一化符号强度；避免固定阈值先删除淡笔画、再将残缺字形放大比较。数字/字母和小花色的最终匹配阈值仍分别为 0.65；内部图案仍在较小画布上评分。两位数字按相邻笔画组件合并，不为 A、6、J 等牌值写特殊规则，也不依赖 OCR 字库。`task2` 设置 `require_corner_indices = true`，通过角标校验的候选优先于未通过的候选，不能被更高的接缝评分替换；最终仍未通过时，返回失败且不生成可发送目标。非标准无角标图案可在直接调用 API 时关闭这个要求。

如果原始角标和细连接开运算都无法找到组合，再检测角标内侧的人像竖框：要求竖向墨迹覆盖足够长，并延伸到小花色下方的角标区域底部，避免将宽字形（例如 `10`）当作边框。只在定位掩膜中排除竖框及其内侧内容，比较仍使用原始连续对比度，字母、小花色和宽高比例阈值不变。`card_queen_index_stacks.yml.gz` 保存最近两轮共九次真实拍摄、按各自拼接姿态采样的浮点角标，用于复现 Q、梅花与人像边框粘连；同时验证缺角标和同向角标仍被拒绝。最终失败的 `error` 和界面日志分别说明哪个角标未提取到，或字形、小花色、比例匹配不足。

`use_layout_pattern` 默认开启：除局部接缝和外框评分外，比较去除角标后的牌面图案在左右镜像、整体 180° 下的印刷结构，选取较一致的一项辅助排序。这是普通点数牌、A 和人物牌的图案先验，不是完整参考图验证；重复、对称或非标准牌面仍可能多解，`unique_solution_verified` 保持为 0。关闭该选项不会跳过显式开启的角标发送前校验。`task2_result.yml` 保存 `corner_indices_verified`、`corner_index_match`、`corner_rank_match`、`corner_suit_match`、`corner_index_aspect_ratio`、`face_pattern_match`、`layout_score` 和 `layout_accepted`，便于区分几何通过和牌面校验通过。

切边上的黑色花纹可能与黑纸亮度相近。为避免截掉梅花等图案，保留原始颜色，并把纹理显示与匹配的掩膜延伸到已有直边模型；模型顶点周围保留实体掩膜，以保留原牌圆角。此纹理补全不改变几何模型、实体掩膜或吸取重心，也不生成新花纹。另存的 `task2_piece_i_texture_mask.png` 记录纹理区域，原 `task2_piece_i_mask.png` 继续记录实体轮廓。

在 `src/perspective.cpp` 的 `task2` 中设置 `CardPuzzleOptions`：`target_size_mm` 为已知牌面宽高，默认零表示按碎片面积和边长估计；默认短边/长边候选范围为 0.50–0.85，可通过 `min_aspect/max_aspect` 调整。新任务不使用白色拼块的 70–120 / 50–90 mm 范围。机械间距通过 `options.gap_mm` 设置，API 默认 5 mm，`task2` 当前设置为 3 mm。扑克牌机械布局限制在当前 A4 校正图的上半区，底边距中心线保留 12 mm（比原位置再上移 10 mm）；展开后必要时整体上移，顶点、重心、平移量、结果图和保存的机械目标同步更新。保持设置的拼块间距；若上半区放不下则返回失败，不生成可发送目标。

识别数据保存在 `card.recognition.pieces`，包括原始重心 `center_gravity`；几何复原为 `card.result`，机械目标为 `card.result_machine`。重心和顶点仍为透视图像的像素坐标；旋转弧度为正表示顺时针。机械展开只平移牌片，保持原始形状和角度。

新任务独立输出：`task2_recognition.png`、`task2_mask.png`、`task2_piece_i.png` / `task2_piece_i_mask.png`、带原图纹理的 `task2_result.png`、`task2_machine.png` 和 `task2_result.yml`。串口起点来自原始牌片重心，终点来自机械结果，沿用 9600 波特率、一位小数、x/y 对换及末尾 `finish\n`。

`task` 调用 `solve_puzzle_in_range`，当前按测试要求，在宽 **70–120 mm**、高 **50–90 mm** 的范围内同时搜索矩形尺寸和拼法。比例仍为每毫米 4 像素，左上角仍为 `(240, 240)`。识别和拼块结果字段沿用原接口。

第二题正式规则的宽度下限为 **90 mm**。当前扩大到 70 mm 是为了支持约 80×70 mm 的测试碎片；正式测评时，应将 `src/perspective.cpp` 中 `min_size` 的 `70.0f` 改回 `90.0f`。实际启用的范围始终记录在 `puzzle_result.yml` 中。

尺寸候选结合碎片边长组合、总面积和覆盖容差生成，并保留不同长宽比。先保留原有较粗尺寸候选的快速搜索。若首轮没有合格布局，在深搜回退前补充一轮按一个位置容差去重（默认 5 像素）的尺寸候选，避免遗漏仍需分别尝试的 5–10 像素尺寸差异；补充轮的完整布局进入联合精调前也为每个尺寸保留候选，防止初始评分把其他尺寸全部挤出最终搜索束。两轮共享原有时间与节点预算，不因补充轮重新计时。回归测试保存 `task2_bv7ocyuh/attempt_0001` 当次识别出的浮点顶点，直接验证自动尺寸求解；另保留两次完整相机照片。保存的 JPG 再解码会改变边缘像素，不能单独作为现场识别结果的精确复现。每轮最多 16 组尺寸，两轮共用同一份搜索预算（task1 为 8 秒，task2 为 30 秒；均为 30000 节点）；完整布局拟合时，宽高也可在规定范围内小幅调整。尺寸由识别几何估计，可能带小数，不强制取整到厘米或毫米。

两个任务返回 `bool`，表示求解与机械目标保存是否成功。主程序退出码：0 为成功，1 为拍照/识别/求解失败（UI 会重新拍照），2 为参数、文件系统或程序异常（UI 停止并显示日志）。`--dry-run` 保留为兼容参数，所有识别调用均不发送串口。

成功后通过 `result.target` 读取最终矩形（像素坐标）：

```cpp
float width_mm = result.target.width / scale;
float height_mm = result.target.height / scale;
```

已知准确尺寸时，仍可直接调用原来的 `solve_puzzle(polygons, target, options)`。该接口保持固定尺寸，不进行尺寸搜索。自动尺寸求解失败时 `result.target` 为空。

- 保留识别出的浮点顶点，仅允许旋转和平移，不缩放、不翻面，也不强制修成直角。
- 大块优先尝试，但其位置和方向不是固定答案。由外框边、已放拼块的边生成候选，尝试边端点和中心对齐，不要求整条外框边由一块补满。
- 先用束搜索保留多套布局（固定尺寸最多 32 套，自动尺寸最多 64 套，并保留尺寸多样性），每个源拼块保留最多 16 个有区别的候选姿态，避免在一个错误分支上深搜到超时。候选阶段允许少量临时偏差，完整布局再联合拟合；临时范围不用于最终验收。束搜索没有成功且预算未耗尽时，再尝试原来的回退搜索。
- 对接近的外框/接缝对齐角度，还会尝试二者的折中方向，避免测量误差使“单边完全对齐”失效。每套完整候选最多用 250 毫秒进行小步旋转、平移；最终重新执行原始全部几何与面积验收。失败的候选不能覆盖有效结果。
- 凹多边形先三角剖分后计算交叠，避免凸包填掉凹槽。只接受简单、非退化的轮廓。
- 所有拼块放置后，再检查目标区域覆盖率、重复占用和框外面积。未通过验收时继续搜索。

| 顶点超出外框的最大距离 | 5 像素 |
| 接缝方向差 | 4 度 |
| 最低覆盖率 | 97% |
| 总重叠面积上限 / 外框面积 | 2% |
| 单对拼块接缝误差面积上限 | 接缝长度 × 位置容差 + 位置容差²，同时不能超过全局重叠上限 |
| 框外面积上限 / 外框面积 | 1% |
| 搜索节点上限 | 30000 |
| 搜索时间上限 | task1 为 8 秒；task2 调用时设为 30 秒 |

覆盖率和最终面积统计使用两倍分辨率的像素中心采样近似，按扫描线半开区间填充，不将轮廓额外计为一条像素带。统计仍有采样误差。识别几何有误差时，结果可能有小缝隙或少量接缝重叠；通过容差验收不代表数学上的无缝铺满。

搜索是有预算的候选枚举，不保证任意拼块集合都能找到解。超时或没有满足条件的候选会明确报告失败，不输出未经确认的摆法。可以根据相机标定误差调整容差，不宜单纯放宽阈值来掩盖识别问题。

## 输出

- `Line Segment.png`：识别得到的原位置线段。
- `lines.png`：求解得到的外框及确认成功的最终拼块，按源轮廓编号着色；自动尺寸失败时画布为空，不绘制未经确认的外框。
- `puzzle_result.yml`：成功状态、搜索上限状态、节点数、求解耗时、输入拼块数量/面积/原始顶点、覆盖率、重叠和框外面积、每块的源轮廓编号、旋转角度、平移量、最终顶点及面积重心 `center_gravity`。`target` 是矩形的像素坐标，`target_size_mm` 是最终宽高（毫米），`target_min_size_mm` / `target_max_size_mm` 是搜索范围。内存中仍通过 `result.placements[i].center_gravity` 读取最终重心（像素坐标）。

报告中的旋转使用 `x' = cos(a)*x - sin(a)*y`、`y' = sin(a)*x + cos(a)*y`，图像坐标中正角是顺时针；先旋转原顶点，再加平移量。它与旧 `Translate` 函数的角度符号约定相反。

旧的逐边放置辅助函数保留，但 `task` 已不再调用它们。

机械执行单独使用 `MachineResult result_machine`（`include/machine_result.hpp`）：

- 原始 `result` 和 `pieces_origin` 保持不变。机械布局仅平移各块，保留源编号、形状和旋转角；`result_machine.placements[i].center_gravity` 为机械目标重心，单位仍为像素，`translation` 和 `points` 同步更新。
- 在 `src/perspective.cpp` 的 `machine_gap_mm = 10.0` 设置拼块边缘的最小间距，单位毫米。按重心方向展开并检查真实多边形距离，各条缝的距离可能不同，但任意两块至少相隔该距离；不缩放拼块。
- 展开后必要时整体平移以放入 A4 工作区；求解失败、无法展开或超出工作区时不发送串口指令。
- `lines.png` 仍显示原始拼图，`lines_machine.png` 显示机械布局。`puzzle_result.yml` 新增 `result_machine` 节点，保存机械布局、就绪状态、最小间距和失败原因。
- 串口使用 `/dev/ttyAMA0`、9600 波特率。起点来自 `pieces_origin`，终点来自 `result_machine`，保留原有 x/y 对换、毫米坐标、顺时针为正的角度值和一位小数格式。全部记录发送成功后才发送 `finish\n`。
